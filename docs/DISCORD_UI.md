# Интерфейс Discord — Verge

## Направление

Спокойное досье: один фирменный фиолетовый акцент, заметные результаты и короткие пояснения. Бот учитывает игровые действия; содержание сцен, исходы конфликтов и канон определяют игроки и ГМы. Формулы, требования тренировок, кулдауны, экономика, права и аудит остаются прежними.

Discord использует собственные шрифты и расположение компонентов. Изображения нужны прежде всего профилю; обычные квитанции и ошибки остаются текстовыми. Палитра веб-портала не меняется.

## Общие элементы

`utils/responseStyle.js` содержит цвета состояний, подписи, форматирование чисел, экранирование пользовательских названий и разбиение текста. Состояние задаётся явно:

| Состояние | Назначение | Цвет |
| --- | --- | --- |
| `info` | Раздел, справка, данные | `#b209d4` |
| `success` | Подтверждённый результат | `#22c55e` |
| `confirm`, `warning`, `unavailable`, `expired` | Подтверждение, предупреждение, ограничение, истечение | `#f59e0b` |
| `error` | Ошибка операции | `#ef4444` |
| `empty`, `closed`, `neutral` | Пустой список, закрытие, нейтральный ответ | `#64748b` |

Цвет всегда сопровождается текстом состояния. Структура карточки: **что произошло → персонаж/объект → результат → существенные подробности → следующий шаг**. Названия кнопок описывают действие: «Подтвердить перевод», «Купить предмет», «Изменить сумму». Недоступность объясняется рядом с кнопкой, пустой список — способом его наполнить.

Для коротких ответов используйте существующий адаптер и его общий шаблон:

```js
import { createStatusComponents } from "../utils/modernResponses.js";

await interaction.reply({
  components: createStatusComponents(
    "Предмет выдан", "Добавлено: **1 шт.**", "success",
    { subject: "**Персонаж · слот 1**", next: "Откройте /inventory, чтобы использовать предмет." },
  ),
  allowedMentions: { parse: [] },
});
```

Приватность задаётся вызывающим обработчиком через `MessageFlags.Ephemeral` согласно существующим правилам команды. Общий шаблон не выбирает аудиторию. Для старых команд остаются `createSuccessEmbed`, `createErrorEmbed`, `createInfoEmbed` и `createResponseEmbed` из `utils/embeds.js`; адаптер преобразует их при отправке. Для сложной карточки используйте общие токены и нативные компоненты, а не второй адаптер. Эвристика по словам сохранена только для совместимости ответов без явного состояния.

## Сценарии

- **Профиль.** Вкладки «Досье», «Физические показатели», «История» переключают текущую панель. «Открыть инвентарь» вынесено в отдельный ряд действий. Есть обновление и переключение изображения/текста. PNG показывает главные показатели; текст содержит точные значения, стили и множители и автоматически заменяет недоступное изображение.
- **AP, SP и социальное РП.** Форма заранее показывает длину текста, базовую награду и интервал. Результат содержит начисление, новое значение, следующую доступность; расчёт и выдержка сцены вынесены в нативный spoiler-контейнер. Числа берутся из `utils/trainingRules.js`, общего для проверки, формы и справки.
- **Магазин.** Цена, количество, баланс, ограничения и способ получения разделены. Покупка предмета и оплата заявки названы по-разному. Возврат из заявок сохраняет категорию, страницу, валюту и товар; после покупки доступен инвентарь. Подтверждение проверяет цену и версию показанного товара.
- **Инвентарь.** Пустое состояние объясняет появление предметов и предлагает обновление. Действия доступны в карточке предмета; повторное открытие читает свежие данные персонажа и инвентаря.
- **Перевод и обмен.** Предварительный расчёт показывает списание, комиссию и зачисление. В переводе можно изменить сумму; устаревшая форма отклоняется. Если новая сумма не отобразилась из-за сбоя Discord, следующее подтверждение сначала обновляет расчёт без списания. Сохранённые сессии и квитанции операций предотвращают повторное выполнение. Неопределённый результат требует проверки той же операции, без изменения суммы или отмены до выяснения результата.
- **Миссии.** Основная карточка показывает состояние, участников и доступность входа. Полные условия открываются отдельно; жизненный цикл и решения ГМа сохраняются.
- **Администрирование.** Выдачи называют персонажа, слот и фактическое изменение. Причина, источник и аудит сохраняются там, где они предусмотрены командой.
- **Справка.** Реестр команд остаётся источником списка; изменённые команды дополнены назначением, условиями и результатом. Игровые числа берутся из общих правил и расчётов.

## Ограничения и надёжность

Актуальные требования: [Discord Component Reference](https://docs.discord.com/developers/components/reference), [Using Message Components](https://docs.discord.com/developers/components/using-message-components), [discord.js Display Components](https://discordjs.guide/legacy/popular-topics/display-components).

- Не более 40 компонентов с учётом вложенных; суммарный текст Text Display — до 4000 символов. Кнопок в ряду до 5, подпись до 80 символов, `custom_id` до 100. У строкового списка до 25 вариантов, подпись и описание до 100 символов.
- Адаптер устанавливает `IsComponentsV2`, сохраняет прочие флаги и очищает legacy-поля при редактировании. Исходная панель, отдельный ответ и follow-up учитываются раздельно. Неудачная отправка не заменяет сохранённую панель.
- Длинные ответы получают явно обозначенное сокращение и полное текстовое вложение. При превышении числа компонентов убирается декоративная вложенность; кнопки и значимые изображения сохраняются. Для длинного ответа нужен свободный слот вложения; занятые десять слотов дают явную ошибку. Файлы в V2 должны быть привязаны через File или Media Gallery.
- Пользовательские названия экранируются; упоминания в преобразованных embed-ответах по умолчанию не пингуют. Отсутствующий или некорректный аватар заменяется безопасным изображением.
- Используйте существующие `interactionRouter` и `interactionSessions`: проверку владельца/роли, сервера и канала, ревизию состояния и claim для значимой операции. Финансовая квитанция привязана к идентификатору операции. Повторное открытие команды само ничего не списывает.
- Истёкшая панель объясняет завершение и команду повторного открытия. Если квитанция успешной операции сохранена, повторное нажатие показывает её, не выполняя операцию заново.

## Локальная проверка

```powershell
npm test
node scripts/preview-discord-ui.mjs
git diff --check
```

Новые проверки в `test/response-standard.test.js` и `test/response-flows.test.js` покрывают лимиты компонентов, флаги/приватность, полные длинные ответы, сбои обновления сообщений, навигацию, владельца/истечение, повторные и одновременные финансовые подтверждения и текстовый профиль при отказе рендера. Интеграционные проверки используют временную MongoDB replica set на локальных тестовых данных.

Скрипт создаёт `.cache/discord-ui/`: PNG обычного/пустого профиля, профиль с длинными именами и большими значениями, физические показатели, JSON фактических payloads для основных разделов. PNG осмотрены локально. Эти файлы не являются скриншотами Discord.

Перед выпуском вручную проверить на тестовом сервере Discord:

1. Телефон и компьютер: переносы текста и кнопок, читабельность PNG, полное текстовое досье, возврат и обновление профиля/магазина/инвентаря.
2. Формы AP/SP/социального РП и изменения суммы: требования до отправки, ошибки, spoiler с расчётом, время следующего действия.
3. Роли игрока/ГМа и чужие панели: видимость миссий, административных ответов, приватных уведомлений и отсутствие лишних пингов.
4. Двойное подтверждение, отмена, истечение и тестовый перезапуск: одна финансовая операция, корректная квитанция и понятное повторное открытие.
5. Пустые списки, удалённый персонаж, недоступный аватар/рендер и длинный ответ с файлом: объяснение состояния и рабочее следующее действие.

Реальный интерфейс Discord, деплой и рабочие данные в рамках локальной реализации не проверялись и не изменялись.
