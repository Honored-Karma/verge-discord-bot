## 🏛️ Обзор архитектуры

Система миссий полностью динамическая и привязана к **организациям из базы данных MongoDB** (коллекции `org_roles` и `custom_orgs`, а также канонические фракции `rankSystem`).

- **Никаких фиксированных ID в `.env`:** Все привязки каналов хранятся в коллекции `organization_mission_settings`.
- **Автоматический Autocomplete:** Новые организации, созданные через `/create-org` или `/org create`, мгновенно становятся доступны в выпадающих списках без перезапуска или передеплоя команд.
- **Отказоустойчивость:** Карточки миссий интерактивны и сохраняют работоспособность при перезапуске бота через `interactionRouter` и базу данных.
- **Атомарность:** Вступление в пати защищено атомарным условием `$expr`, исключающим овербукинг последнего места при одновременных кликах.
- **Конфиденциальность:** В карточках и профилях участников отображаются только публичные данные (Имя, Организация, Ранг, Атрибут, AP, стили, ссылка на веб-профиль). Балансы кошельков, закрытый инвентарь, заметки администрации и внутренние Discord ID скрыты.

## ⚙️ Настройка каналов организаций (Администраторы)

Правом настройки каналов обладают участники с правами `Administrator` или ролями из `ADMIN_IDS`.

### 1. Привязать канал миссий к организации

```text
/mission channel set organization:<организация> channel:<#канал>
```

- Организация выбирается из живого списка autocomplete.
- Бот проверяет, что канал принадлежит данному Discord-серверу.
- Бот валидирует свои права в канале: `ViewChannel`, `SendMessages`, `EmbedLinks` (и предупреждает, если нет прав на создание `PublicThreads`).
- Сохраняется привязка `guild_id + organization_key -> channel_id`.
- Действие логируется в базу данных и канал аудита администрации.

### 2. Удалить привязку канала

```text
/mission channel remove organization:<организация>
```

Отвязывает назначенный канал. После этого создание миссий для данной организации блокируется до повторного назначения канала.

### 3. Просмотреть список привязок

```text
/mission channel list
```

Отображает удобную таблицу всех организаций сервера, статус привязки каналов и доступность публикации для бота.

## 🎲 Создание и проведение миссий (ГМ / Администраторы)

Доступ к созданию и управлению миссиями имеют администраторы, а также участники с ролями ГМ (`LIMITED_ADMIN_ROLE_IDS`).

### Создание миссии (Интерактивный мастер)

```text
/mission create
```

Команда вызывается **без параметров** и открывает персональный интерактивный мастер (Ephemeral-черновик миссии) со всплывающими окнами ввода и выпадающими списками:

1. **Выпадающие списки карточки-черновика:**
   - **Тип миссии:** Скважина (🌀), Набег (⚔️), Расследование (🔍), Фракция (🚩), Социальная (💬), Другое (📜).
   - **Доступ:** Открытая для всех, Только организация, Приглашённые.
   - **Организация:** Живой выбор из базы данных (плюс вариант «Без организации»).
   - **Канал публикации:** Выбор текстового канала (по умолчанию текущий или официальный канал организации).

2. **Всплывающие модальные окна ввода:**
   - **`[📝 Основное]`** — открывает модальное окно:
     - *Название миссии* (до 100 символов).
     - *Лимит участников* (от 1 до 50 чел.).
     - *Описание / вводная* (многострочный текст до 1000 символов).
   - **`[🎁 Награды]`** — открывает модальное окно:
     - *Награда AP*, *Награда SP*, *Награда репутации Rtg*.
     - *Предмет* (название из каталога или кастомное) и *Количество*.

3. **Публикация:**
   - Кнопка **`[🚀 Опубликовать]`** проверяет заполнение обязательных полей (название и описание), валидирует права бота в целевом канале и публикует готовую интерактивную карточку в канал.
   - Кнопка **`[✖️ Отмена]`** отменяет создание и закрывает черновик.

#### Правила выбора канала:
1. При выборе организации из списка бот автоматически подставляет закреплённый за ней канал миссий.
2. Если организация не выбрана, миссия публикуется в выбранный в селекторе канал (или текущий по умолчанию).
3. При публикации в целевом канале автоматически создаётся публичная ветка обсуждения (Thread) при наличии соответствующих прав у бота.

## 👥 Участие игроков и пати

После публикации в канале появляется интерактивная карточка миссии.

### Кнопки карточки:
- **`[Вступить]`**:
  - Использует активный слот персонажа игрока (`user_settings`).
  - Проверяет существование персонажа.
  - Проверяет соответствие организации (при `access: organization`).
  - Блокирует повторное вступление одного пользователя или персонажа.
  - Проверяет лимит участников через атомарную транзакцию MongoDB (защита от race condition).
  - Моментально обновляет счётчик и список участников в карточке.
- **`[Покинуть]`**:
  - Разрешён только на стадии набора (`recruiting`). После старта состав блокируется.
- **`[Состав пати]`**:
  - Ephemeral-панель со списком участников, их организациями и рангами.
- **`[Профили участников]`**:
  - Интерактивный выпадающий список для выбора союзника и просмотра его публичной карточки (атрибут, ранг, организация, AP, стили, ссылка на веб-профиль).
- **`[Начать миссию]`** *(только ГМ/админ)*:
  - Фиксирует состав участников, переводит статус в `active`, создаёт публичную Discord-ветку (thread) для отыгрыша.
- **`[Завершить миссию]`** *(только ГМ/админ)*:
  - Открывает ГМу подтверждение состава и наград.
  - После подтверждения автоматически начисляет награды всем участникам.
- **`[Отменить]`** *(только ГМ/админ)*:
  - Переводит миссию в статус `cancelled`, отключает кнопки вступления, награды не начисляются.

## 🔄 Жизненный цикл и состояния

```text
[ recruiting ]  ──(ГМ нажал «Начать»)──>  [ active ]  ──(ГМ нажал «Завершить»)──>  [ completed ]
      │                                         │
      └──(ГМ нажал «Отменить»)──────────────────┴──(ГМ нажал «Отменить»)──────────>  [ cancelled ]
```

- **`recruiting`** — Открыт набор участников. Игроки могут вступать и выходить.
- **`active`** — Отыгрыш начался. Состав зафиксирован, кнопки вступления и выхода заблокированы. Создан тред для игры.
- **`completed`** — Миссия завершена. Награды автоматически начислены в базу данных.
- **`cancelled`** — Миссия отменена ГМом. Награды не выдаются.

## 🎁 Идемпотентная выдача наград

Выдача наград использует атомарный реестр транзакций `reward_delivery` внутри документа миссии.

Для каждого участника и каждого типа награды формируется детерминированный ключ:
- `mission:<public_id>:<player_id>:ap`
- `mission:<public_id>:<player_id>:sp`
- `mission:<public_id>:<player_id>:reputation`
- `mission:<public_id>:<player_id>:item`

### Защита от сбоев:
1. **Никаких прямых `$set`**: Используются штатные функции `addAP`, `addSP`, `addReputation`, `addItem`.
2. **Идемпотентность**: Если награда с данным ключом уже помечена как выданная, повторный вызов (клик ГМа, сетевая ошибка Discord, перезапуск бота) пропускает её.
3. **Частичный сбой**: Если начисление одному из участников завершилось ошибкой (например, сбой соединения с БД), статус участника помечается как `failed`.
4. **Безопасный повтор (Retry)**: ГМу отображается кнопка **«Повторить выдачу»**, которая производит начисление **только** для неудавшихся записей, не дублируя уже успешно выданные награды другим игрокам.
5. **Финализация**: Миссия получает статус `completed` только тогда, когда все начисления успешно завершены.

  "message_id": "112233445566778899",
  "thread_id": "112233445566778800",

### 2. Коллекция `organization_mission_settings`
Хранит привязку каналов миссий к организациям в разрезе Discord-серверов.

```json
{
  "guild_id": "123456789012345678",
  "organization_key": "tenryu",
  "organization_name": "Tenryū",
  "channel_id": "987654321098765432",
  "updated_by": "111111111111111111",
  "updated_at": "2026-09-07T14:00:00.000Z"
}
```

**Индексы `organization_mission_settings`:**
- `{ guild_id: 1, organization_key: 1 }` (unique)
- `{ guild_id: 1, channel_id: 1 }`
