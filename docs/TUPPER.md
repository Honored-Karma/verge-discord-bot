# Профили для отыгрыша

## Создать профиль

Введите `/vupper` или `/vupper action:create`. В форме доступны только:

- имя персонажа;
- аватар файлом или ссылкой;
- начальный и конечный маркеры.

Например: имя `Ая`, начальный маркер `ая:`, конечный пустой. Сообщение `ая: Привет!` будет отправлено с именем и аватаром Аи. Для скобок задайте начало `[` и конец `]`: `[Привет!]`.

Заполните хотя бы один маркер. Пробелы и регистр учитываются. Аватар необязателен; поддерживаются PNG, JPEG, GIF и WebP до 8 МиБ.

## Изменить или удалить профиль

- `/vupper action:edit profile:…` — изменить имя, аватар и маркеры своего профиля.
- `/vupper action:delete profile:…` — удалить свой профиль после подтверждения его имени.

Если `profile` не указан, откроется список ваших профилей. Выберите профиль и действие в меню. Доступны только создание, изменение и удаление. Изменить или удалить чужой профиль нельзя.

В `/vupper` больше нет импорта, экспорта, JSON-форм, групп, автопрокси, серверных настроек и публичного просмотра чужих профилей. Формы и действия из старых меню отклоняются. Существующие записи автоматически не удаляются. Старые режимы автопрокси, ники и теги групп не применяются: сообщения отправляются по маркерам с именем профиля.

JSON и блоки `{{…}}` в репликах отправляются как обычный текст: вставки, броски кубиков и перенаправление в другой канал не выполняются.

## Сообщения

В меню сообщения → «Приложения» доступны изменение своего отыгрыша, удаление и просмотр автора. Авторство сохраняется после удаления профиля. Удалить сообщение также может модератор с правом «Управлять сообщениями» в канале. Для действий нужны актуальный доступ к каналу и его истории; доступ к приватной ветке проверяется отдельно.

## Запуск

1. Установите зависимости: `npm ci`.
2. Включите Message Content Intent и Server Members Intent в Discord Developer Portal.
3. Выдайте боту права просмотра канала, чтения истории, отправки сообщений, управления сообщениями и вебхуками. Для веток нужно право отправки сообщений в ветках; для медиа — соответствующие права вложений и вставок.
4. Для загрузки файлов аватаров нужен публичный HTTPS `WEB_BASE_URL` с доступным `/api/avatar/…`. Без него можно указать постоянную внешнюю HTTPS-ссылку.
5. Перезапустите бота: команды обновляются при запуске. Отдельная регистрация — `npm run deploy`.

MongoDB должна поддерживать транзакции (replica set / Atlas). Токены вебхуков в MongoDB не сохраняются.

Проверки: `node --test test/tupper.test.js`; общий набор — `npm test`.
