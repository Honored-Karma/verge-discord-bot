# Профили для отыгрыша

## Быстрый старт

1. Введите `/tupper`. Откроется одна форма: имя, файл аватара, ссылка на аватар, начальный и конечный маркеры.
2. Например, укажите имя `Ая`, начальный маркер `ая:`, конечный оставьте пустым.
3. Отправьте `ая: Привет!` в текстовый канал сервера. Бот заменит сообщение на `Привет!` с именем и аватаром Аи.
4. Для настройки уже созданных профилей выберите у `/tupper` действие **«Открыть все профили»**. Выберите персонажа и действие в меню. Изменения вносятся через формы.

Файл имеет приоритет над ссылкой. Пустая ссылка без нового файла убирает аватар. Поддерживаются PNG, JPEG, GIF и WebP до 8 МиБ. Аватары и баннеры сохраняются в MongoDB; временная ссылка на вложение Discord не используется как постоянный адрес. Если публичный адрес веб-сервера ещё не настроен, можно использовать постоянную внешнюю HTTPS-ссылку; её доступность будет зависеть от исходного хостинга.

Профили не занимают игровые слоты. Действие **«Создать из игрового персонажа»** переносит имя и аватар активного слота в форму создания. Дальше профиль отыгрыша и игровой персонаж редактируются независимо.

Лимиты: 5000 профилей, 500 групп, 30 пар маркеров на профиль. Имя и ник — до 80 символов, тег — до 32. Импорт — до 2 МиБ. Вставки ограничены правилами Discord: до 10 и до 6000 символов суммарного текста.

## Маркеры и автопрокси

Для скобок задайте начало `[` и конец `]`: `[Привет]`. Начальный или конечный маркер может быть пустым, одновременно оба — нет. Пробелы и регистр учитываются. Совпадающие пары у разных собственных профилей запрещены; при пересечении выбирается наиболее длинная подходящая пара.

В форме всех маркеров пары записываются плоским JSON-массивом:

```json
["ая:", "", "[", "]"]
```

Пустой массив убирает ручные маркеры, сохраняя возможность автопрокси. Если вы изменяете основную форму такого профиля, оба пустых поля сохранят этот режим.

Мультипрокси:

```text
ая: Привет!
боб: Добрый вечер.
```

Фиксированный режим отправляет обычные сообщения выбранным профилем. Липкий запоминает последнего явно использованного персонажа **в текущем канале**. `\текст` пропускает одно сообщение, `\\текст` также сбрасывает липкий выбор либо выключает фиксированный режим для этого канала. Команды, начинающиеся с `!`, `/`, `$`, `?` или `имя!`, автопрокси пропускает.

Форма настроек загружает локальные значения текущей области. При смене области в списке все значения формы применятся к новой выбранной области. «Наследовать» восстанавливает значение более широкой области. Эффективный режим можно посмотреть через действие **«Проверить права и настройки»**.

## Сообщения и модерация

- **Изменить отыгрыш** открывает форму текста. Изменять сообщение может только его реальный автор. Файлы и вставки при изменении текста сохраняются.
- **Удалить отыгрыш** открывает подтверждение. Доступно автору либо модератору с правом «Управлять сообщениями» в этом канале.
- **Кто автор отыгрыша?** показывает автора приватным ответом.
- ❓ отправляет автора в личные сообщения; ❌ удаляет сообщение; 📝 отправляет в личные сообщения кнопку открытия формы редактирования. Если личные сообщения закрыты, используйте меню сообщения.

Авторство хранится по ID сообщения, а не определяется по имени вебхука. Оно сохраняется после удаления профиля. Просмотр требует актуального доступа к каналу и истории; доступ к приватной ветке проверяется отдельно. Новое сообщение вебхука не отправляет повторные пинги.

Журнал содержит автора, имя профиля и ссылку. Текст приватных сцен в журнал не копируется. Настройка журнала: `/tupper`, действие **«Настроить сервер»**, ID текстового канала.

Правила задаются отдельной формой JSON:

```json
[
  {"scope":"default","feature":"proxies","allow":false},
  {"scope":"role","id":"123456789012345678","feature":"proxies","allow":true}
]
```

`feature`: `commands`, `proxies` или `queries`. `scope`: `default`, `role`, `channel`, `user`; `id` нужен для всех, кроме `default`. Порядок приоритетов: default → роли → канал → пользователь. При конфликте правил на одном уровне запрет побеждает. Пустой массив восстанавливает стандартные разрешения. Администратор с «Управлять сервером» может открыть серверные настройки напрямую, даже если `commands` запрещены общим правилом.

## Импорт и приватность

Список профилей **скрыт по умолчанию**. Для публичного списка выберите нужную область в настройках и выключите «Скрывать список профилей от других». Это не скрывает автора уже отправленного сообщения. Явная публикация карточки доступна и для скрытого профиля: форма сообщает, какие данные попадут в канал.

Импорт объединяет данные по нормализованным именам: совпавшие профили и группы обновляются, остальные сохраняются. Невалидные данные, одинаковые маркеры и превышение лимита отменяют весь импорт. Настройки приватности и авторство старых сообщений из чужих ботов не импортируются.

Из PluralKit переносятся общие данные персонажей, маркеры, аватары, баннеры, даты и счётчики. При нескольких группах используется первая подходящая: модель Tupperbox предполагает одну группу на персонажа. Лимиты имён и тегов соответствуют этой реализации; слишком длинные значения требуют исправления в файле. Ссылки на внешние изображения при импорте сохраняются как ссылки. Для собственного постоянного хранения загрузите изображение через форму профиля.

Экспорт соответствует структуре Tupperbox `tuppers` / `groups`. Дополнительные `banner_url`, `position`, `groups[].avatar_url` сохраняют данные при переносе между установками Verge; сторонний импортёр может игнорировать эти расширения. Для переноса группового аватара в чужой бот может потребоваться повторная загрузка.

## Запуск

1. Выполните `npm ci` после обновления исходников.
2. Включите **Message Content Intent** и **Server Members Intent** в Discord Developer Portal. Бот уже использует эти intents для остальных функций.
3. Выдайте боту «Просматривать канал», «Читать историю сообщений», «Отправлять сообщения», «Управлять сообщениями», «Управлять вебхуками». Для веток нужно «Отправлять сообщения в ветках». Для вложений и вставок нужны соответствующие права.
4. Для загрузки файлов аватаров настройте публичный HTTPS `WEB_BASE_URL`, по которому доступен Express-сервер бота и `/api/avatar/…`. `localhost` Discord недоступен. Без публичного адреса работают текстовые профили и постоянные внешние HTTPS-ссылки на изображения; загрузка файла сообщит о настройке.
5. Перезапустите бот. Индексы MongoDB создаются автоматически; команды регистрируются существующим механизмом запуска. Можно выполнить `npm run deploy` отдельно.
6. Проверьте `/tupper`, затем одну реплику с маркером в тестовом канале и три действия из меню сообщения.

MongoDB должна поддерживать транзакции (replica set / Atlas), как и для экономики бота. Дополнительные переменные окружения и отдельный сервис вебхуков не нужны. Токены вебхуков не записываются в MongoDB и экспорт.

## Поведение при сбоях и ограничения

Отправка резервируется по ID исходного сообщения. После каждой подтверждённой части сохраняется её авторство. Только после подтверждения **всех** частей удаляется исходный текст. При неоднозначном сетевом результате автоматического повторения нет: исходное сообщение и уже отправленные части нужно проверить перед ручным повтором. Доставка Discord и запись MongoDB не образуют общей транзакции; абсолютная гарантия «ровно один раз» для внешнего API не заявляется.

Обычный текст длиннее 2000 символов разбивается без разрыва пары UTF-16; общий предел — 30 частей. Стикеры оставляются в исходном сообщении с пояснением. Закрытые ветки не открываются автоматически. Кадрирование сохраняет PNG до 2048 пикселей по длинной стороне; анимированный GIF при обрезке становится статичным.

Баннер и описание отображаются в карточках бота. Системную всплывающую карточку пользователя Discord вебхук не может заменить. Управление реализовано внутри Discord; отдельного веб-кабинета Tupperbox здесь нет.

Расширенные броски выполняются в отдельном worker с пределами времени, памяти и параллелизма. Для `@dice-roller/rpg-dice-roller` закреплён override `mathjs >=15.2.0`: он закрывает известные уязвимости парсера выражений, совместимость проверена тестом бросков.
